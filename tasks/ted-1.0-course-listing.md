## User Story

身為自由教練，我想快速設定上課地點、時段與人數並發布，讓學員直接在平台報名付款，省去在 LINE 或 FB 個別私訊與對帳的時間。

## 規格

1. **開課欄位**：課程名稱、運動項目（MVP 多元包含重訓、瑜珈為主、抱石、衝浪、跑酷）、上課地點（場館名稱＋地址，供 Google Map 定位）、日期、可授課時間區間、課程時程（每堂課長度）、運動程度（不限／初級／中級）、每人費用（單堂）、人數下限與上限、報名截止時間（預設開課前 24hr，可提前）、課程介紹、以及相關課程須知（穿著、裝備）。
2. **場次產生**：教練課程上架時，依時間區間、課程時程以及地點綁定固定場次。例：「XX 球館，14:00–17:00，課程 1 小時」產生 14:00、15:00、16:00 三個場次，每個場次各自計算名額與成團。
3. **課程範本與複製**：教練可將課程存為範本，或複製既有課程後修改日期再發布。
4. **課程管理**：教練工作台「我的課程」依狀態（招生中／已成團／已結束／已取消）列出各場次，可查看報名人數與學員名單（名稱／暱稱與報名時間）、編輯課程（場次有人報名後，僅能編輯公告與 QA）、取消場次（條件見下方規則）、以及對該場次學員群發公告（7.0，暫不做，先留 UI 掛勾即可）。
5. **聯絡資訊過濾**：課程名稱、課程介紹等公開欄位禁止填寫 LINE ID、電話、Email 或外部連結。
6. **開課極簡化**：流程簡化設計，幾分鐘內即可完成發布；發布後可分享開課頁連結（10.0，這次先不做分享功能本體，保留欄位／路由即可）。
7. **教練取消場次**：開課前 48hr 以上且尚未成團時，教練可在課程管理頁手動取消場次；已報名學員的報名直接取消（未扣款），並收到課程取消通知。開課前 48hr 內或已成團後，系統不提供取消按鈕。

## 驗收標準（AC）— 與 claude.ai Project 的 `驗收標準-AC總表.md` 一致

- [ ] 必填欄位（課程名稱、運動項目、地點、日期、時間區間、課程時程、每人費用、人數上下限）齊全後發布按鈕才可點擊；發布後課程狀態為「招生中」，並出現在學員端列表。
- [ ] 從範本或複製建立課程時，除日期外的欄位自動帶入，教練可修改後發布。
- [ ] 課程管理頁面中每個場次顯示即時報名人數與學員名單，名單不顯示學員聯絡方式。
- [ ] 距開課 48hr 以上且尚未成團的場次，才顯示「取消場次」按鈕；取消後場次改為「已取消」，所有報名改為「已取消（未扣款）」並通知學員。

## 這個任務會踩到的 corner case（PRD 系統規則總覽裡列的，自我驗收時別漏）

- 人數上限不可低於已報名人數（編輯時要擋）。
- 必填欄位留空時，發佈按鈕要是 disabled，不是送出後才報錯。
- 場次「有人報名後」只能編輯公告與 QA，時段／地點／價格／人數都鎖住——這條邏輯依賴 `registrations` 表有沒有該場次的有效報名紀錄（Task 00 schema 已經有這張表，可以直接查，不需要等 3.0 報名功能的 UI 做完）。
- 教練取消場次的「尚未成團」判斷：MVP 階段 3.0（報名與成團）還沒開發，所以這次先用「該場次報名人數 < 人數下限」當作「尚未成團」的簡化判斷依據，等 3.0 做完後再對齊正式的成團狀態欄位。

## 跳單防範（聯絡方式過濾）

公開欄位（課程名稱、課程介紹、課程須知）偵測到以下任一就要擋下並提示，不能送出：
- 電話號碼格式
- LINE ID（含「line」「@」等常見標記）
- Email 格式
- 外部網址（http/https、常見短網址）

文案可沿用 PRD：「為保障雙方交易安全，請勿於公開欄位填寫個人聯絡資訊」。

`courses`、`registrations` 兩張表已經在 Task 00 建好（見 `supabase/migrations/`），這次主要是在這兩張表上面做 CRUD 與場次邏輯，原則上不需要再動 schema；如果發現欄位不夠用（例如缺人數上下限、報名截止時間等欄位），**先跟 Ted 自己確認要不要加 migration，不要直接在 UI 任務裡偷加欄位**（雖然這次是同一個人，但保持習慣，之後換別人接手比較不會忘記在哪裡改過 schema）。
